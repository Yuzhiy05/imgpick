# imgpick 项目学习笔记

## 项目概述

imgpick 是一个使用 Slint + Rust 开发的 Windows 桌面图片标价应用，支持图片管理、标价、Excel 配对等功能。通过这个项目的开发，我学到了很多关于 Slint UI 框架、Rust 异步编程、文件处理等方面的知识。

### 技术栈
- **UI框架**: Slint 1.16.1
- **数据库**: SQLite (rusqlite, bundled feature)
- **Excel处理**: calamine
- **图片处理**: image crate
- **文件对话框**: rfd
- **异步运行时**: tokio
- **日期时间**: chrono
- **序列化**: serde, serde_json

## 一、Slint UI 框架深度学习

### 1.1 基础语法详解

Slint 是一个声明式的 UI 框架，语法类似于 JSON 和 CSS 的结合体。

**组件定义**：
```slint
export component MyComponent inherits Rectangle {
    // 属性定义
    in-out property <string> text: "";
    in-out property <int> count: 0;
    in-out property <bool> is-selected: false;
    in-out property <image> preview-image;
    
    // 回调定义
    callback clicked();
    callback data-changed(string, int);
    
    // 样式属性
    width: 100px;
    height: 30px;
    background: is-selected ? #e3f2fd : #fafafa;
    border-radius: 4px;
    border-width: 1px;
    border-color: #e0e0e0;
    
    // 子组件
    VerticalLayout {
        padding: 8px;
        spacing: 4px;
        
        Text {
            text: root.text;
            font-size: 14px;
            color: #333;
            horizontal-alignment: center;
            vertical-alignment: center;
        }
    }
}
```

**属性类型详解**：
- `<string>`: 字符串类型，Rust中对应 `slint::SharedString`
- `<int>`: 32位整数，Rust中对应 `i32`
- `<float>`: 浮点数，Rust中对应 `f64`
- `<bool>`: 布尔值，Rust中对应 `bool`
- `<image>`: 图片类型，Rust中对应 `slint::Image`
- `<[string]>`: 字符串数组，Rust中对应 `slint::ModelRc<slint::SharedString>`
- `<[int]>`: 整数数组

**回调参数类型**：
```slint
callback clicked();                           // 无参数
callback item-clicked(int);                   // 单个参数
callback data-changed(string, int);           // 多个参数
callback result-ready([string], bool);        // 复杂参数
```

### 1.2 全局单例详解

全局单例用于在 Rust 和 Slint 之间传递数据，是整个应用的数据中枢：

```slint
export global PlanPageAdapter {
    // 属性定义
    in-out property <[PlanData]> plans: [];
    in-out property <int> plan-columns: 6;
    in-out property <int> selected-plan-id: 0;
    in-out property <string> status-message: "";
    
    // 回调定义
    callback create-plan(string);
    callback delete-plan(int);
    callback rename-plan(int, string);
    callback select-plan(int);
    
    // 内联函数（pure function不触发UI更新）
    pure function validate-name(name: string) -> bool {
        return name != "";
    }
}
```

**Rust端访问**：
```rust

app.global::<ui::PlanPageAdapter>().set_selected_plan_id(plan_id as i32);
app.global::<ui::PlanPageAdapter>().set_status_message("操作成功".into());

// 获取属性

let plans = app.global::<ui::PlanPageAdapter>().get_plans();

// 注册回调
app.global::<ui::PlanPageAdapter>().on_create_plan(move |name| {
    let name_str = name.to_string();
    // 处理逻辑...
});

// 调用回调
app.global::<ui::PlanPageAdapter>().invoke_create_plan("新计划".into());
```

**属性命名转换规则**：
- Slint: `plan-columns` → Rust: `plan_columns`
- Slint: `status-message` → Rust: `status_message`
- Slint: `selected-plan-id` → Rust: `selected_plan_id`

### 1.3 条件渲染详解

```slint
// 简单条件
if condition: Rectangle {
    background: #e3f2fd;
}

// 带else的条件
if is-selected: Rectangle {
    background: #1976D2;
}
if !is-selected: Rectangle {
    background: #f5f5f5;
}

// 复杂条件
if count > 0 && has-data: VerticalLayout {
    // 内容...
}

// 嵌套条件
if expanded: VerticalLayout {
    if has-items: ScrollView {
        // 内容...
    }
    if !has-items: Text {
        text: "暂无数据";
    }
}
```

**条件渲染的性能考虑**：
- 条件为false时，组件不会被渲染
- 频繁切换的条件可能导致性能问题
- 复杂条件应该提前计算

### 1.4 循环渲染详解

```slint
// 基本循环
for item[i] in items: Rectangle {
    Text {
        text: item.name;
    }
}

// 带索引的循环
for item[i] in items: Rectangle {
    background: i == selected-index ? #e3f2fd : transparent;
    Text {
        text: item.name;
        color: i == selected-index ? #1976D2 : #333;
    }
}

// 嵌套循环
for category[i] in categories: VerticalLayout {
    Text { text: category.name; }
    for image[j] in category.images: Rectangle {
        Text { text: image; }
    }
}
```

**循环渲染的注意事项**：
- 模型为空时需要用 `if` 条件守卫
- 索引 `i` 从0开始
- 模型变化时会自动重新渲染
- 大量数据时考虑使用 ScrollView

## 二、组件拆分尝试与失败

### 2.1 问题描述

`app.slint` 文件达到 2800+ 行，尝试拆分为多个文件：
- `structs.slint` - 数据结构定义
- `globals.slint` - 全局适配器定义
- `plan/plan_page.slint` - 计划管理页面
- `pricing/pricing_page.slint` - 图片标价页面
- `manage/manage_page.slint` - 图片管理页面
- `excel/excel_page.slint` - Excel配对页面

### 2.2 失败原因详解

**1. 全局单例引用问题**
```slint
// globals.slint
export global PlanPageAdapter {
    // 定义...
}

// plan/plan_page.slint
import { PlanPageAdapter } from "../globals.slint";

// main.rs - 这里会失败！
app.global::<ui::PlanPageAdapter>().set_plans(...);
```

Slint编译器会将所有类型放在 `ui` 模块中，但跨文件引用时路径解析失败。

**2. 导入路径限制**
```slint
// 相对路径导入可能失败
import { PlanData } from "../structs.slint";

// std-widgets.slint 不需要导入
// TouchArea, GridLayout, Timer 等是内置组件
```

**3. main.rs 类型引用依赖**
```rust
// Rust中引用Slint类型
use slint::ComponentHandle;

// 类型必须在编译时被正确生成
app.global::<ui::PlanPageAdapter>()
//          ^^^^^^^^^^^^^^^^^^^^
//          这个类型必须在ui模块中存在
```

### 2.3 结论

由于 Slint 的模块系统限制，`app.slint` 必须保持单文件结构。

**关键经验**：
- Slint的模块系统还不够成熟
- 全局单例必须定义在主文件中
- 组件拆分会导致类型引用失败
- 2800+行虽然较长，但功能模块边界清晰

## 三、Excel导入功能深度实现

### 3.1 Excel文件解析

使用 `calamine` 库读取 Excel 文件：

```rust
use calamine::{Reader, open_workbook, Xlsx, Data as CellData};

pub fn read_excel_file(path: &Path) -> Result<Vec<ExcelRow>, String> {
    let mut workbook: Xlsx<_> = open_workbook(path)
        .map_err(|e| format!("Failed to open Excel file: {}", e))?;
    
    let sheet_names = workbook.sheet_names().to_vec();
    if sheet_names.is_empty() {
        return Err("Excel file has no sheets".to_string());
    }
    
    let sheet_name = &sheet_names[0];
    let range = workbook.worksheet_range(sheet_name)
        .map_err(|e| format!("Failed to read sheet: {}", e))?;
    
    let mut rows = Vec::new();
    let mut headers = Vec::new();
    
    for (i, row) in range.rows().enumerate() {
        if i == 0 {
            // 第一行作为表头
            for cell in row {
                let header = match cell {
                    CellData::String(s) => s.clone(),
                    CellData::Float(f) => f.to_string(),
                    CellData::Int(i) => i.to_string(),
                    _ => String::new(),
                };
                headers.push(header);
            }
            continue;
        }
        
        // 处理数据行
        let mut data = HashMap::new();
        for (j, cell) in row.iter().enumerate() {
            let value = match cell {
                CellData::String(s) => s.clone(),
                CellData::Float(f) => f.to_string(),
                CellData::Int(i) => i.to_string(),
                CellData::Bool(b) => b.to_string(),
                CellData::Error(e) => format!("Error: {:?}", e),
                CellData::Empty => String::new(),
                _ => String::new(),
            };
            data.insert(headers[j].clone(), value);
        }
        
        rows.push(ExcelRow { data });
    }
    
    Ok(rows)
}
```

### 3.2 列名自动检测

支持多种列名格式，自动检测列名行：

```rust
// 关键词列表
let keywords = [
    "sampleid", "sample_id", "样本编号", "samplebarcode", "样本id",
    "孔位1", "孔位2", "孔位3", "考察时间", "检测时间",
    "testholeresult", "testtime"
];

// 尝试前3行作为列名备选
let max_check_rows = all_rows.len().min(3);
let mut header_row_index = -1;

for check_row in 0..max_check_rows {
    let row = &all_rows[check_row];
    let mut found_keywords = 0;
    let mut temp_headers = Vec::new();
    
    for cell in row {
        let header = match cell {
            CellData::String(s) => s.clone(),
            CellData::Float(f) => f.to_string(),
            CellData::Int(i) => i.to_string(),
            _ => String::new(),
        };
        
        let header_lower = header.to_lowercase();
        
        // 检查是否包含关键词
        for keyword in &keywords {
            if header_lower.contains(keyword) {
                found_keywords += 1;
                break;
            }
        }
        
        temp_headers.push(header);
    }
    
    // 如果找到至少2个关键词，认为这是列名行
    if found_keywords >= 2 {
        header_row_index = check_row as i32;
        headers = temp_headers;
        eprintln!("找到列名行: 第{}行，包含{}个关键词", check_row + 1, found_keywords);
        break;
    }
}
```

**关键经验**：
- 不同Excel文件的列名格式可能不同
- 需要支持多种列名格式
- 自动检测列名行可以提高用户体验
- 前3行检查可以覆盖大部分情况

### 3.3 孔位结果合并

孔位结果分散在多个列中，需要合并：

```rust
// 查找所有孔位列
let mut hole_columns: Vec<(usize, i32)> = Vec::new();

for (j, header) in headers.iter().enumerate() {
    let header_lower = header.to_lowercase();
    
    for hole_num in 1..=8 {
        let patterns = vec![
            format!("孔位{}", hole_num),
            format!("孔位_{}", hole_num),
            format!("hole{}", hole_num),
            format!("hole_{}", hole_num),
        ];
        
        for pattern in &patterns {
            if header_lower.contains(pattern) {
                hole_columns.push((j, hole_num));
                eprintln!("找到孔位列: 第{}列 '{}' -> 孔位{}", j + 1, header, hole_num);
                break;
            }
        }
    }
}

// 按孔位编号排序
hole_columns.sort_by_key(|&(_, num)| num);

// 合并孔位结果
let mut hole_result_parts: Vec<(i32, String)> = Vec::new();
for &(col_idx, hole_num) in &hole_columns {
    if let Some(value) = row.get(col_idx) {
        hole_result_parts.push((hole_num, value.clone()));
    }
}

if !hole_result_parts.is_empty() {
    hole_result_parts.sort_by_key(|&(num, _)| num);
    let hole_result: Vec<String> = hole_result_parts.iter()
        .map(|(_, v)| v.clone())
        .collect();
    let hole_result_str = hole_result.join(",");
    // "-,-,4+,-,4+,4+,-,-"
}
```

**关键经验**：
- 孔位列可能分散在不同位置
- 需要按孔位编号排序后再合并
- 支持8孔（血型）、3孔（抗筛）、2孔（交叉配血）

### 3.4 Excel日期时间转换

Excel的日期时间是序列号格式，需要转换：

```rust
use chrono::{NaiveDate, NaiveTime, NaiveDateTime};

CellData::DateTime(dt) => {
    // Excel日期基准是1899年12月30日
    let value = dt.as_f64();
    let excel_epoch = NaiveDate::from_ymd_opt(1899, 12, 30).unwrap();
    
    // 分离日期和时间部分
    let days = value as i64;
    let fractional = value - days as f64;
    let seconds = (fractional * 86400.0) as u32;
    
    // 转换为日期时间
    if let Some(date) = excel_epoch.checked_add_days(chrono::Days::new(days as u64)) {
        let time = NaiveTime::from_num_seconds_from_midnight_opt(seconds, 0).unwrap_or_default();
        let datetime = date.and_time(time);
        datetime.format("%Y-%m-%d %H:%M:%S").to_string()
        // 输出: "2026-02-02 16:44:48"
    }
}
```

**关键经验**：
- Excel日期基准是1899年12月30日（不是1900年1月1日）
- `as_f64()` 方法获取数值
- 小数部分表示时间（0.5 = 12:00:00）
- 46055.69777777778 = 2026-02-02 16:44:48

## 四、图片匹配功能深度实现

### 4.1 时间格式匹配

根据考察时间查找对应的图片：

```rust
/// 解析文件名中的时间部分
/// 文件名格式：2026-04-09-12-25-49.jpg
/// 返回：2026-04-09 12:25:49
fn parse_time_from_filename(filename: &str) -> Option<String> {
    // 移除扩展名（使用 split 而不是 rsplit）
    let name = filename.split('.').next().unwrap_or(filename);
    
    // 分割日期和时间部分
    let parts: Vec<&str> = name.split('-').collect();
    if parts.len() >= 6 {
        let date = format!("{}-{}-{}", parts[0], parts[1], parts[2]);
        let time = format!("{}:{}:{}", parts[3], parts[4], parts[5]);
        Some(format!("{} {}", date, time))
    } else {
        None
    }
}
```

**关键经验**：
- `split('.').next()` 获取文件名主体
- `rsplit('.').next()` 获取扩展名（方向相反）
- 移除扩展名应该用 `split` 而不是 `rsplit`
- 文件名格式：`2026-04-09-12-25-49-679.jpg`

### 4.2 价位完全匹配

```rust
fn match_by_price(
    hole_result: &str,
    images: &[Image],
    category: &str
) -> Vec<ImageCandidate> {
    let target_slots: Vec<&str> = hole_result.split(',').collect();
    let mut candidates = Vec::new();
    
    for image in images {
        // 只匹配同种类的图片
        if let Some(ref img_category) = image.sample_id {
            if img_category != category {
                continue;
            }
        } else {
            continue;
        }
        
        if let Some(ref price) = image.price {
            let image_slots: Vec<&str> = price.split(',').collect();
            
            // 完全匹配检查
            if target_slots.len() == image_slots.len() {
                let mut all_match = true;
                for (t, c) in target_slots.iter().zip(image_slots.iter()) {
                    if t != c {
                        all_match = false;
                        break;
                    }
                }
                
                if all_match {
                    candidates.push(ImageCandidate {
                        file_name: image.file_name.clone(),
                        file_path: image.file_path.clone(),
                        match_score: 100,
                        category: category.to_string(),
                    });
                }
            }
        }
    }
    
    candidates
}
```

## 十一、问题解决经验总结

### 11.1 Slint相关

1. **全局单例必须定义在主文件中**
2. **组件的回调需要在使用处显式绑定**
3. **`vertical-stretch` 需要在父容器和子组件上都设置**
4. **`split` 和 `rsplit` 方向相反**
5. **右键使用 `pointer-event` 而不是 `clicked`**
6. **条件渲染使用 `if` 而不是 `visible`**
7. **循环渲染空模型需要条件守卫**

### 11.2 Rust相关

1. **`PathBuf` 传入函数后会被移动，需要 `clone()`**
2. **`let _ =` 忽略错误返回值**
3. **`VecModel::set_vec()` 原地更新避免模型替换崩溃**
4. **使用 `Arc` 共享数据库连接**
5. **`SharedString` 和 `String` 之间的转换**
6. **模型迭代使用 `.iter().collect()`**

### 11.3 Excel相关

1. **Excel日期是序列号格式，需要chrono库转换**
2. **calamine的 `DateTime` 类型需要 `as_f64()` 方法**
3. **孔位列可能分散在不同位置**
4. **列名需要支持多种格式**
5. **考察组和对照组数据需要正确分离**

### 11.4 文件处理相关

1. **删除文件使用 `let _ =` 忽略错误**
2. **复制文件使用 `std::fs::copy`**
3. **创建目录使用 `std::fs::create_dir_all`**
4. **遍历目录使用 `std::fs::read_dir`**

## 十六、开发心得

### 16.1 技术选择

1. **Slint + Rust** 是一个好的组合，但Slint还不够成熟
2. **SQLite** 足够轻量，适合桌面应用
3. **calamine** 是最好的Rust Excel库
4. **tokio** 是必须的异步运行时

### 16.2 开发流程

1. **先设计数据结构**，再实现UI
2. **先实现核心功能**，再添加细节
3. **频繁测试**，避免问题累积
4. **及时记录**，避免遗忘

### 16.3 问题解决

1. **仔细阅读错误信息**，大部分问题都能从错误信息中找到线索
2. **分步调试**，不要一次修改太多
3. **查阅文档**，很多问题都有现成的解决方案
4. **记录问题**，避免重复犯错
